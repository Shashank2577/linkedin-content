## Post body (copy from here)

I don't let a team skip agent evals. Ever.

Tarn Adams, who makes Dwarf Fortress, said in a 2013 Reddit AMA: "I don't use version control." The reason given was code going into a black box with no immediate upside. In 2016 Adams told PC Gamer: "I don't even use version control." In a 2023 Game Developer interview ahead of the Steam release, Adams said there was "version control stuff to use now" and that the process was "a little more involved."

Ten years from "no" to "fine, I'll use it."

Evals are where agents are right now. They feel like overhead with no immediate upside, right up until a change to a prompt or a model quietly breaks something nobody was watching.

My rule is simple. Before an agent touches a real workflow, there's a set of cases it has to pass, and the same set runs on every prompt, tool or model change. Twenty cases is enough to start. Zero is the number that hurts.

It's my rule, not an industry standard.
